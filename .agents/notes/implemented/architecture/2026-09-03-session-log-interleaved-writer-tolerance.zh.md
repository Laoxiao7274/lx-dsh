# Agent Note：会话日志读取容忍第二写入者游标分歧产生的行

Status: implemented

中文 | [English](2026-09-03-session-log-interleaved-writer-tolerance.md)

## 问题

同一存储根目录下的十个已存储会话在每次打开时都以 `seq gap in committed region` 失败。JSONL 后端的单写者互斥**只在进程内**生效（`JsonlBackendTracker.claimWrite`）；两个后端进程指向同一 `~/.dsh` 会话根目录——打包版 LX-DSH 实例与 dev 实例——各自以自己的内存游标持有同一会话，追加的行在磁盘上交错出三种实测形态：

1. 外部冷打开补写的 `session/end-seed` 标记落在活跃写入者的游标处；活跃写入者的下一行重覆盖该 seq（`expected N, got N`）。
2. 一个进程执行的截断移除了另一进程已经越过的 seq（`expected N, got N+k`），特征是恰好移除被中断轮次的 `turn/end`，其后紧跟下一轮次的 `step/start`。
3. 200 ms 延迟的实时事件缓存在外部追加之后排空，陈旧行落到流中间（一个日志中最多交错 27 行）。

既有读取契约把已提交区域的每种不连续都当作致命错误——此前针对这些类别的帧级 salvage（见 [2026-08-28 salvage 笔记](2026-08-28-session-log-salvage.md)）在上游 handle-seam 重构重写该包时被丢弃——于是每次碰撞都让会话永久无法打开。

## 决策

`SessionLogScanner` 在行粒度上确定性吸收写入者分歧，每次读取都如此：

- 首个 seq 重覆盖已扫描 seq 的行作为陈旧行丢弃——除非被覆盖的保留前缀只由 `session/end-seed` 标记组成（纯边界元数据、不承载内容）：此时丢弃标记、接纳到来的内容行。这是形态 1 的无损合并。
- 空洞尺寸恰好等于保留前缀的 `interruptedTurnClosers` 时——形态 2 的签名——用这些合成 closer 桥接，但仅当空洞所在行开启比当前开启轮次更晚的轮次（唯一能合法跟随合成 `turn/end` 的内容）；否则扫描停在持久切口，提供保留前缀。
- 不可解析的行被丢弃；下一行的 seq 决定其后是否出现空洞。
- 停止的扫描通过 `issueError()` 报告空洞；读取方把它映射到写缝的既有修复（空洞所在帧起始的 `tornTruncateTo` 加 `recoveredTail`），首次 append 持久截断并重写产物。`readZstdPrefix` 改用 `scanZstdFramesSalvage` 扫描，结构损坏的帧同样变成切口而不是整份拒绝。

行级容忍优于此前的帧级方案（对形态 1、3），因为帧级切口会丢弃整批——对标记碰撞，它要为删除一行冗余而扔掉 74 000 个事件。切口仍是空洞的后备，因为 seq 是事件身份：不重编号历史就无法跳过空隙。

读取在吸收了行时记录警告（`read tolerating N stale log row(s)`）并指名会话，让共享根目录的部署可观察，而不是无声自愈。

## 考虑过的替代方案

**跨进程写锁。** 写句柄持有的锁文件或字节区间认领可以预防分歧而非容忍。暂缓：持久化缝把进程内互斥写为契约，且崩溃遗留的锁会引入新的"无法打开"失败模式、需要自己的恢复故事。容忍还能修复在锁发布之前已经损坏的日志。

**读取时修复产物。** 读取时重写文件能清洁磁盘，但让只读句柄变成变更者、与并发读取竞争，并可能为一行冗余重追加整个尾部。读取在内存中归一化；写缝在下一次 append 时修复。

**桥接每个恰好吻合的空洞。** 没有"更晚轮次"条件，轮次中间的空洞后跟同轮次内容会产出合成 `turn/end`，让日志剩余部分表面无效。`turn/start`/`step/start` 且轮次编号更大，是所有真实损坏文件中观察到的判别特征。

## 后果

- 两个进程共享存储根目录不再让会话变砖：标记碰撞无损读取、单 `turn/end` 空洞整体桥接、其余空洞退化为分歧前的前缀而不是拒绝。
- 吸收的分歧把外部字节留在磁盘上；每次读取都确定性重新归一化，直到写打开经截断缝修复产物。
- 不可解析行不再毒化日志剩余部分：随后续接 seq 序列的行被保留。
- `compression: 'none'` 编码经 `scanLog` 获得相同语义；该路径的 `tornTruncateTo` 是最后接纳行的末字节。
- 发现并留待单独处理的独立缺陷：`SessionStore.rewind` 发出 `session/truncate`，但**任何包都没有监听者**——rewind 从不截断持久日志，写句柄游标失同步，缓冲的实时路由此后每次排空都因 `assertContiguous` 失败直到重启。修复它需要独立的缝决策，超出本次范围。

## 验证

`packages/session/session-persistence-jsonl/tests/jsonl.spec.ts` 把已提交区域拒绝类测试改写为 salvage 契约（吸收行 + 保留前缀 + `issueError`，替代抛出），并新增扫描器级陈旧行丢弃与标记回退用例。`tests/zstd.spec.ts` 新增后端级用例：外部标记与活跃写入者行碰撞（无损读取、不修复、下次 append 持久愈合）、单事件空洞被合成 `turn/end` 桥接（复用最后真实事件的时间戳）、不可桥接空洞退化为前缀并由写路径截断。四个 spec 文件全部通过（198 项）；session 域套件通过（1448 项，两个无关的 projection-cache 偶发用例在隔离运行中通过）。
