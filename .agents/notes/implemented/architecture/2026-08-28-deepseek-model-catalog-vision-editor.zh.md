# Agent Note：DeepSeek 模型目录编辑器声明视觉能力，并改为卡片化外观

状态：已实现

[English](2026-08-28-deepseek-model-catalog-vision-editor.md) | 中文

## 问题

直连 DeepSeek 适配器的 schema 允许每个目录模型声明请求模态（`inputModalities: ('text' | 'image')[]`，默认 `['text']`），但设置编辑器完全没暴露它：模型的视觉支持在 UI 里既不可见也不可编辑；目录行本身也只是裸边框盒子加永久带框输入框——能用，但比其他设置卡片都吵。

## 决策

每行一个视觉 chip——带眼睛图标的药丸按钮，`aria-pressed` 语义；容量面板里同一声明还有一个带标签的 `role="switch"`。开启写入 `inputModalities: ['text', 'image']`（与已有条目合并）；关闭移除 `image`，当只剩文本默认值时把整个字段清掉，使未修改的行保持干净的继承态而不是积累一个显式 `['text']`。该字段和 `contextWindow` 一样是 `Record<string, unknown>` 草稿成员：编辑器整体替换数组、只碰自己拥有的键，因此隐藏或未来的字段在编辑后保留。

目录改为账本式外观而不是盒子叠盒子：一个描边容器，行与行之间用发丝线分隔（行自身无边框），模型 ID 用等宽字体，行内字段平时无框、hover/focus 才描边，容量披露为齐平的内嵌块。编辑卡片本身被拍平：原先折叠的「自定义设置」抽屉不复存在——连接字段（密钥、Base URL、协议）与模型目录是同一张卡片的两个分区，中间一条发丝线，目录始终可见。行入场为短暂的 gsap 滑入（首次渲染交错、追加单行滑入）、披露滑出、视觉 chip 切换弹跳、编辑卡开启上浮、提供商列表挂载时交错入场——所有动效包裹在 `gsap.context()` 里（ui-primitives Modal 先例），并受共享 `motionAllowed()` 读数门控——`prefers-reduced-motion` 与测试通道只见结构。编辑器私有打包 gsap（`dependencies`），这是动态行在模块表之外引入动画库的既许路径。

## 考虑过的替代方案

**自由文本的模态字段。** 直接暴露原始数组供编辑能零定制逻辑地往返每个字段值，但模态在实践中是二值事实（这个模型收不收图片）——自由文本字段招来保存时才被 schema 拒绝的笔误，而且一眼看不出当前处于哪个状态。chip/开关对用一次点击陈述同一事实。

**只做目录重排版，不加视觉开关。** 目录账本化与模态字段正交；只发货版式会把底层缺口（声明视觉能力没有 UI 通路）原样留下——那正是引发本次改动的用户可见缺陷。

## 后果

- 两个编辑器族的用户都可以从设置 UI 按模型声明视觉能力；适配器的 schema 校验仍是保存时的唯一权威。
- 两族写入的字段与语义不同，chip 因此是共享组件、切换动作归各家族所有：DeepSeek 行写 `inputModalities`（关闭清空字段——适配器默认恒为纯文本），pi-ai 行写 `input`——显式列表会**替换**已安装目录的声明，因此关闭写入确定性的 `['text']` 而不是清空字段，清空会重新武装目录里记录的任何模态。
- 行入场为短暂的 gsap 滑入（首次渲染交错、追加单行滑入）、容量披露滑出、视觉 chip 切换弹跳——两个编辑器持有同一动效模式，受共享 `motionAllowed()` 读数门控。
- 模态列表含意外值的行，切换只影响列表中 `image` 的增删，其余不动；schema 仍在 apply 时拒绝任何非法值。
